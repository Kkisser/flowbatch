# flowbatch

Пакетная генерация изображений и видео в Google Flow поверх **живой залогиненной
сессии браузера**. Скрипт не поднимает свой браузер, не использует headless и не
автоматизирует логин Google — он подключается по CDP к уже открытой вкладке.

---

## 1. Запуск браузера

Подойдёт любой браузер на Chromium. Проверено на **Edge 150**.

```bash
"/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" --remote-debugging-port=9222 --user-data-dir="C:/edge-flow-profile"
```

Chrome — то же самое, свой путь и своя папка профиля.

**Про профиль — важно.** `--user-data-dir` обязан указывать на **не дефолтную**
папку. Chromium 136+ (и Edge 136+) игнорируют `--remote-debugging-port`, когда
браузер работает на профиле по умолчанию. Следствие: это отдельный чистый
профиль, и в Google в нём нужно **один раз залогиниться руками**. Дальше сессия
живёт в этой папке и переживает перезапуски.

Обычные окна браузера при этом можно не закрывать: другой `--user-data-dir`
запускается отдельным независимым процессом.

После логина открой в этом окне нужный проект Flow
(`labs.google/fx/ru/tools/flow/project/<id>`). Скрипт сам найдёт эту вкладку
среди открытых — URL проекта в конфиг вписывать не нужно. Новых вкладок он не
открывает и никуда не навигирует.

## 2. Установка

```bash
py -3.13 -m venv .venv && .venv/Scripts/python -m pip install -r requirements.txt
```

Браузер Playwright скачивать не нужно: работаем поверх твоего.

## 3. `.env`

Скопируй `.env.example` в `.env` и заполни:

```
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...
```

Токен — у [@BotFather](https://t.me/BotFather) (`/newbot`), `chat_id` — у
[@userinfobot](https://t.me/userinfobot). Если переменных нет, уведомления молча
отключаются и прогон это не блокирует. `.env` в git не попадает.

## 4. `jobs.yaml`

```yaml
- id: s01_hero
  kind: image
  prompt: "Vertical 9:16 still. ..."
  refs: []

- id: s01_anim
  kind: video
  prompt: "The camera slowly pushes in ..."
  refs: ["out/s01_hero.png"]
  duration: 8        # 4 | 6 | 8 | 10; без поля — из config.yaml
```

- `id` уникален и служит именем файла в `out/`.
- `refs` — пути к локальным файлам. **Расширение можно не угадывать**: если
  точного пути нет, ищется сосед с тем же именем и любым расширением. Это важно,
  потому что расширение результата задаёт Flow — картинка часто приезжает `.jpg`,
  а не `.png`. Референс, который уже лежит в библиотеке Flow, файлом не нужен:
  спека `lib:<имя>` (или `lib:<проект> :: <имя>`) прикрепит его прямо из
  библиотеки — это то же, что директива `@lib` в текстовом формате.
- Если `ref` указывает на файл, скачанный прошлой задачей, flowbatch найдёт его
  в библиотеке Flow по media-uuid из `runs.jsonl` и **не будет заливать повторно**.
  Для постороннего файла (например, фото товара) он сначала зальёт его в
  библиотеку, потом прикрепит.

## 5. Команды

```bash
.venv/Scripts/python -m flowbatch.cli doctor
```

Ничего не генерит. Проверяет CDP, вкладку, логин, каждый селектор поимённо,
текущие модель/формат/количество и Telegram. Если селектор не нашёлся — печатает
**актуальную разметку этого места** и останавливается, а не подбирает замену.

```bash
.venv/Scripts/python -m flowbatch.cli newproject --name "Название проекта"
```

Создаёт новый пустой проект и остаётся в нём. Диалога Flow не показывает —
проект появляется сразу, имя по умолчанию это дата и время создания, поэтому
`--name` опционален.

**Это единственная команда, которая навигирует по приложению.** `run` сам никуда
не уходит, если ему явно не передан `--new-project`.

```bash
.venv/Scripts/python -m flowbatch.cli run --dry-run --only s01_hero
```

Всё, кроме клика «Создать»: настройки выставлены, промпт введён и
верифицирован, референсы прикреплены, формат проверен. Кладёт скриншот
состояния в `screenshots/`.

```bash
.venv/Scripts/python -m flowbatch.cli run
```

Флаги: `--jobs FILE`, `--only ID`, `--from ID`, `--limit N`, `--dry-run`,
`--no-resume`, `--config FILE`, `--new-project`, `--project-name NAME`.

`--new-project` создаёт пустой проект и гонит очередь в нём. Резюм при этом
отключается автоматически: в новом проекте ничего не сгенерировано, и старый
`runs.jsonl` пропустил бы задачи, которых там нет.

**Резюм включён по умолчанию.** Задачи со статусом `ok` в `runs.jsonl`
пропускаются. Убитый на середине прогон достаточно перезапустить той же
командой. Отключается через `--no-resume`.

## 5a. Веб-панель

```bash
.venv/Scripts/python -m flowbatch.cli ui --source ZASTRYALO_S01E02_UIPATH_QUEUE.xlsx
```

Открывает `http://127.0.0.1:8765` — таблица очереди со статусами, фильтры по
типу и батчу, Старт/Стоп, живой лог и галерея результатов. Источник очереди —
`.xlsx`, `.yaml` или `.txt` с @-директивами; текст можно вставить прямо в
панель. Прогон крутится в фоновом потоке, страница опрашивает состояние.

**Галочки решают, что генерить.** Отмеченные строки запускаются ровно как
отмечены — даже со статусом DONE (это явное «перегенерить»). Без галочек идут
все строки TODO. Фильтры тип/батч/лимит применяются поверх. Статусы при
загрузке очереди подтягиваются: для Excel — из колонки 03_STATUS, для
yaml/текста — из runs.jsonl (а при объявленном проекте — по этому проекту,
уже на старте прогона).

Ещё в панели: сортировка кликом по заголовку любой колонки (второй клик —
обратный порядок, третий — сброс), «✕» у строки убирает её из очереди (файл
не меняется, «Загрузить» возвращает всё), встроенная справка по dry-run,
BATCH и лимиту, и блок «Подключение к браузеру» — там меняется CDP-endpoint.

**Проекты.** Очередь может объявить свой проект Flow: `@project <имя>` в
текстовом формате или `PROJECT_NAME` на листе SETTINGS в Excel. Перед прогоном
панель (и `run`) откроет этот проект, а при отсутствии — создаст. CLI-флаг
`--project NAME` перебивает и то и другое.

**Как дать программу другому человеку.** Токены не нужны и не поддерживаются
сознательно: авторизация Flow живёт в session-cookies залогиненного браузера,
а access_token из `__NEXT_DATA__` короткоживущий и браузерную сессию не даёт —
вставка его в панель ничего бы не включила, а хранение чужих токенов — дыра.
Рабочая схема: человек клонирует репозиторий, ставит зависимости, запускает
СВОЙ браузер с `--remote-debugging-port` и отдельным `--user-data-dir`
(раздел 1), один раз логинится в Google и указывает свой порт в панели в блоке
«Подключение к браузеру». Всё — дальше программа работает с его аккаунтом.

«Стоп» доигрывает текущую задачу и останавливается перед следующей — паузы
между задачами прерываются сразу, ждать пять минут не придётся.

Сервер слушает **только 127.0.0.1** и отдаёт файлы исключительно из `out/` и
`screenshots/`. Наружу его выставлять нельзя: он управляет твоим браузером.

## 5b. Очередь из Excel

```bash
.venv/Scripts/python -m flowbatch.cli run --sheet ZASTRYALO_S01E02_UIPATH_QUEUE.xlsx
```

Читает листы `IMG_QUEUE` и `VID_QUEUE`, берёт строки со статусом `TODO`,
сортирует по `02_ORDER` (картинки раньше видео). Пишет обратно `03_STATUS`,
`20_RESULT_PATH`, `22_TIMESTAMP`, а при ошибке инкрементит `21_ATTEMPTS` и
кладёт текст в `23_NOTES`. Имя файла берётся из `19_OUTPUT_NAME`.

Дополнительные флаги: `--batch BATCH_A`, `--kind image|video`.

Резюм при `--sheet` идёт по колонке `03_STATUS`, а не по `runs.jsonl`.

**Многострочные промпты можно брать напрямую из `17_PROMPT`.** `PROMPT_MODE=ONELINE`
и трюк с буфером обмена нужны UiPath, потому что `Type Into` жмёт настоящий
Enter и форма улетает раньше времени. Здесь текст вставляется через
`insert_text`, событий клавиш не возникает вообще — проверено посимвольно на
промпте в 2228 знаков с 14 переводами строк.

### Формулы в книге

`16_REF_LIST` и `15_REF_COUNT` — формулы (`TEXTJOIN`, `COUNTA`). openpyxl не
умеет писать формулы вместе с кэшем результата, поэтому любая запись статуса
обнулила бы их вычисленные значения, и `Read Range Workbook` в UiPath увидел бы
пустоту. Отсюда два решения:

- **читаем референсы из исходных колонок** `11_REF_HEROES`…`14_REF_PRODUCT`,
  а не из формулы — так очередь не зависит от кэша вовсе;
- **при первой записи формулы замораживаются в свои значения.** Данные
  сохраняются полностью, теряется только автопересчёт. Если после прогона
  править колонки `REF_*` руками, `16_REF_LIST` сам не обновится — пересобирай
  очередь из исходного файла.

### Кэш референсов

Одни и те же 4 файла используются в 7 строках 14 раз. Чтобы не залить их 14 раз
и не намусорить дублями, путь разрешается так:

1. файл — результат прошлой задачи **в этом же проекте** → uuid из `runs.jsonl`;
2. файл уже заливался в этот проект и не менялся → uuid из
   `.flowbatch_refcache.json` (ключ — путь + mtime + размер);
3. иначе заливаем и запоминаем.

Кэш и лог фильтруются по `project_id`: **uuid действителен только внутри своего
проекта**, в новом проекте тот же файл получит другой uuid.

## 5c. Промпты текстом: формат с @-директивами

Третий источник очереди, под сценарий «промпты пишет LLM».
**Полная документация формата — [PROMPT_FORMAT.md](PROMPT_FORMAT.md)**
(семантика якорей, все ошибки разбора, полный пример эпизода, готовый шаблон
для LLM-генератора). Ниже — краткая выжимка. Файл `.txt` (или
текст, вставленный прямо в панель):

```
=== IMG K1
@ref C:\RVL\ZASTRYALO\S01E02\refs\E01_0A_geroi4.png
@ref C:\RVL\ZASTRYALO\S01E02\refs\E02_0C_kost.png
Vertical 9:16 frame. Многострочный промпт как есть...

=== VID K1_anim
@use K1
@duration 8
Animate this image. ...
```

| Директива | Что делает |
|---|---|
| `=== IMG <id>` / `=== VID <id>` | начало блока (синонимы: КАРТИНКА, ФОТО, ВИДЕО) |
| `@ref <путь>` | прикрепить локальный файл референсом (можно несколько) |
| `@use <id>` | прикрепить **результат другой задачи**: из этого же файла или готовый `out/<id>.*` от прошлых прогонов |
| `@duration 4\|6\|8\|10` | длительность видео |
| `@out <имя>` | имя файла результата (по умолчанию — id) |

Директивы вычищаются из текста до отправки — во Flow уходит только промпт.
**Строки, начинающиеся с `#`, тоже вырезаются везде** (Flow иначе рисует их
текстом на картинке); решётка в середине строки остаётся, а `\#` в начале
строки — экранирование для промпта, которому решётка нужна.
Неизвестная `@`-строка — ошибка разбора, а не часть промпта: опечатка в
директиве не утечёт в генерацию молча. Разбор атомарный: есть ошибки — очередь
не собирается, панель показывает список с номерами строк.

Запуск: `run --prompts scenes.txt` либо вставка в панель → «Разобрать и
загрузить» (текст сохраняется в `prompts_pasted.flow.txt` и переживает рестарт).

### Шаблон инструкции для твоего LLM-генератора промптов

Вставь этот блок в системный промпт модели, которая пишет сцены:

```
Выдавай результат строго в формате flowbatch. Каждая сцена — блок:
строка «=== IMG <короткий_id>» для картинки или «=== VID <короткий_id>» для видео,
затем директивы, затем текст промпта. Директивы:
@ref <абсолютный путь к файлу-референсу> — эталоны персонажей и фото продукта;
@use <id ранее описанной IMG-сцены> — у видео всегда первой директивой, это кадр-источник;
@duration 8 — у каждого VID-блока.
Никакого другого текста между блоками. id — латиница/цифры/подчёркивание,
у видео id = <id кадра>_anim. Промпт пиши многострочным, переводы строк разрешены.
```

## 6. Как прогнать тесты

```bash
.venv/Scripts/python tests/test_scrub.py
```

Проверяет, что секреты вычищаются из текста ошибок, а диагностика остаётся.

Ручная проверка на живой странице — по шагам, не прыгая вперёд:

| Шаг | Команда | Что должно получиться |
|---|---|---|
| 0 | `doctor` | все селекторы найдены, формат `crop_9_16`, `x1` |
| 1 | `run --dry-run --only <image-id>` | скриншот, «Создать» активна, но не нажата |
| 2 | `run --only <image-id>` | валидный файл в `out/`, запись `ok` в `runs.jsonl` |
| 3 | `run --only <video-id>` | mp4 720x1280, длительность = заданной |
| 4 | `run --jobs jobs.test.yaml`, убить, перезапустить | вторая попытка пропускает выполненное |

## 7. Что важно знать про поведение Flow

Всё ниже проверено на живой странице, а не выведено из документации.

**Формат и количество выставляются скриптом автоматически** перед каждой
задачей и затем перечитываются из текста кнопки как жёсткий гейт: если после
установки там не `crop_9_16` и не `x1`, задача падает и не запускается.

**Режим «Видео» меняет модель.** В изображениях это `🍌 Nano Banana 2`, в видео —
`Omni Flash`, и имени модели в тексте кнопки уже нет:

| Режим | Текст кнопки | Стоимость |
|---|---|---|
| Изображение | `🍌 Nano Banana 2 / crop_9_16 / x1` | 0 бонусов |
| Видео | `Видео · 8s / crop_9_16 / x1` | 12 бонусов |

Поэтому селектор кнопки настроек **не** привязан к имени модели, а ищется по
`button[aria-haspopup="menu"]:has-text("crop_")` — работает в обоих режимах.

**Референсы прикрепляются не через `input[type=file]`.** Этот input грузит файл
в **библиотеку** проекта. Прикрепление к запросу — отдельный flow: кнопка «+» →
пикер медиа → выбор строки → «Добавить в запрос». Строки пикера несут точный
media-uuid в `src` превьюшки, поэтому выбор идёт по uuid, а не по имени.

**«Очистить запрос»** снимает и промпт, и все прикреплённые референсы. Скрипт
жмёт её перед каждой задачей, иначе референсы предыдущей утекают в следующую.

**Свежие результаты встают в НАЧАЛО библиотеки**, а не в конец.

**`getMediaUrlRedirect` отвечает 307 на каждое успешное обращение.** Правило
«всё, что не 2xx — ошибка» валит любую удачную задачу. Ошибками считаются
только 4xx/5xx.

**Селекторы, по которым нельзя работать:** классы `sc-*` (хэши
styled-components), id `radix-:r7i:` (генерятся заново при каждом рендере),
XPath. Табы в меню настроек адресуются по стабильному хвосту `aria-controls`
(`-content-PORTRAIT`, `-content-VIDEO`, `-content-8`).

**`data-testid="virtuoso-scroller"` неоднозначен**, когда открыт пикер: такой же
есть внутри диалога. Библиотека везде выбирается с фильтром
`:not(внутри [role=dialog])`.

## 8. Безопасность

`access_token` из `__NEXT_DATA__` не читается в Python — из JS возвращается
только булев флаг его наличия. Он нигде не логируется и не сохраняется.

Отдельно: при сетевой ошибке Playwright печатает call log целиком, **вместе с
заголовком Cookie**, а там лежит `__Secure-next-auth.session-token`. Одна такая
трассировка в `runs.jsonl` или в Telegram отдаёт сессию Google целиком. Поэтому
весь текст ошибок проходит через `flowbatch/scrub.py` на каждой границе:
сообщение исключения, `runs.jsonl`, Telegram. Проверяется тестом
`tests/test_scrub.py` на реальном образце утёкшей трассировки.

В `.gitignore` добавлены `*.out`, `*.err`, `*.log` — перенаправленный вывод
процессов туда же попадает.

reCAPTCHA Enterprise v3 на странице невидимая и скорит поведение молча. Она не
решается и не обходится — вместо этого держится человеческий темп: паузы с
джиттером, низкая параллельность, никаких лишних кликов по UI.

## 9. Реакция на ошибки

| Что пришло | Реакция |
|---|---|
| `PUBLIC_ERROR_UNSAFE_GENERATION` | смягчение промпта → повтор (см. ниже); не помогло — FAILED, очередь дальше |
| `USER_QUOTA_REACHED` | **очередь останавливается**, уведомление |
| `PUBLIC_ERROR_UNUSUAL_ACTIVITY` | **очередь останавливается**, совет пауза 1–6 ч |
| 429 / 5xx / сетевой сбой | экспоненциальный бэкофф, до 3 ретраев |

Сбой скачивания ретраится **отдельно от генерации**: результат уже в библиотеке,
повторять надо только загрузку файла. Иначе каждая сетевая икота на видео стоила
бы лишних 12 бонусов.

## 9a. Модерация: детект и смягчение промптов

Отказ модерации Flow приходит двумя путями, и ловятся оба:

1. **Сетевой код** в ответе tRPC (`PUBLIC_ERROR_UNSAFE_GENERATION`).
2. **Надпись на странице** («это видео может нарушать наши правила») — при
   этом HTTP бывает успешным. Ловится сканом текста страницы по списку фраз
   из `moderation.phrases` в config.yaml. Считается только **прирост** фраз
   после клика «Создать» — старые упавшие плитки не дают ложных срабатываний.
   Увидел новую формулировку — добавь её в список; текст ошибки задачи всегда
   содержит кусок страницы вокруг найденной фразы.

Поймав отказ, программа сообщает (консоль, панель, Telegram) и **смягчает
промпт** — переписывает его безобиднее и перезапускает ту же задачу, до
`moderation.soften.attempts` раз. Бэкенды смягчения (`moderation.soften.backend`):

| Бэкенд | Цена | Что делает |
|---|---|---|
| `rules` | бесплатно, офлайн | попытка 1 — смягчающая приписка к промпту; попытка 2 — ещё и замены слов из конфига (`knife`→`spoon`…) |
| `gemini` | бесплатный тариф | Gemini переписывает промпт целиком, сохраняя сцену, реплики и бренд. Ключ: aistudio.google.com/apikey → `GEMINI_API_KEY=` в `.env` |
| | | ⚠️ Подписка **Google AI Pro/Ultra** (та, что даёт Flow и Gemini Advanced) ключа не заменяет: по документации Google планы для AI Studio отделены от тарифов Gemini API — подписка поднимает лимиты в веб-студии, а программе нужен ключ. Бесплатного тарифа ключа для смягчения хватает с запасом. |
| `claude` | платный | то же через Claude API (`ANTHROPIC_API_KEY` + `pip install anthropic`) |
| `auto` (по умолчанию) | — | Gemini, если есть ключ; иначе Claude, если есть ключ; иначе правила |

LLM-бэкенд при любой ошибке (нет сети, кончился дневной лимит) молча падает
на правила — смягчение не может уронить задачу. Реплики персонажей и бренд
Revyline инструкцией защищены от переписывания. Отключить: `--no-soften` в CLI
или `moderation.soften.enabled: false` в конфиге.

**Проверка ключа без браузера и без генераций:**

```bash
.venv/Scripts/python -m flowbatch.cli soften-test
```

Показывает, какие ключи видны в `.env` (значения не печатаются — только длина),
какой бэкенд выбран, жив ли ключ, есть ли у него модель из конфига (если нет —
печатает список доступных, чтобы вписать рабочую), и прогоняет заведомо «злой»
промпт через смягчение, показывая до/после. Свой промпт: `--prompt "..."`.

Ключ передаётся заголовком `x-goog-api-key`, а не параметром `?key=` в URL:
новые ключи AI Studio создаются как auth-keys (старые standard-keys Google
отключает в сентябре 2026), и заголовок не оставляет ключ в URL, логах прокси
и текстах ошибок.

После успешного прохода со смягчённым промптом в Telegram уходит «прошло после
смягчения», в лог — чем именно смягчали. Если все попытки исчерпаны — задача
FAILED с текстом «промпт смягчался N раз — не помогло», очередь идёт дальше.

## 10. Ограничения

**`antiban.concurrency > 1` не реализован.** В одной вкладке одно поле промпта,
и при параллельном запуске становится неоднозначно, какой из появившихся
результатов какой задаче принадлежит. Значение больше 1 не деградирует молча —
`run` останавливается с объяснением. Потолок 3 в конфиге валидируется.

**Детект готовности — по диффу медиа-URL**, а не по идентификатору задачи. При
`x1` это однозначно. Если выставить `x2`+, за запуск появится несколько новых
элементов, и в `out/<id>` попадёт только первый.
