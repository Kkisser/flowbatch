# Формат промптов flowbatch (@-директивы)

Это формат, в котором программе присылаются промпты на генерацию. Один текст —
вся очередь эпизода: картинки, видео и связи между ними. Программа сама
разбирает его, прикрепляет нужные референсы и прогоняет через Google Flow.

Куда подавать:

- **веб-панель** → «Вставить промпты текстом» → «Разобрать и загрузить»;
- **файл** `.txt` → `python -m flowbatch.cli run --prompts scenes.txt`.

Разбор атомарный: если в тексте есть хоть одна ошибка, очередь не собирается,
а панель показывает список ошибок с номерами строк. Это защита от молчаливых
опечаток — кривой блок не уедет в генерацию «как получилось».

---

## 1. Структура

Текст состоит из блоков. Блок = заголовок + директивы + промпт:

```
=== IMG K1
@ref C:\RVL\ZASTRYALO\S01E02\refs\E01_0A_geroi4.png
@ref C:\RVL\ZASTRYALO\S01E02\refs\E02_0C_kost.png
Vertical 9:16 frame. Cinematic 3D animated cartoon...
Многострочный текст промпта, переводы строк сохраняются
и уходят в Flow дословно.

=== VID K1_anim
@use K1
@duration 8
Animate this image. The camera slowly cranes upward...
```

### Заголовок блока

```
=== IMG <id>     — картинка
=== VID <id>     — видео
```

Синонимы типов (регистр не важен): `IMG`, `IMAGE`, `КАРТИНКА`, `ФОТО`, `КАДР` —
картинка; `VID`, `VIDEO`, `ВИДЕО` — видео.

`<id>` — уникальное имя задачи: латиница, цифры, `_`, `.`, `-`. Оно же станет
именем файла результата: `out/<id>.jpg` у картинок, `out/<id>.mp4` у видео
(расширение выбирает Flow по типу медиа — не угадывай его заранее).

### Комментарии

Строки, начинающиеся с `#`, игнорируются **между блоками и до начала текста
промпта**. Внутри текста промпта `#` — обычный символ и остаётся в промпте.

---

## 2. Директивы (якоря)

Директива — строка внутри блока, начинающаяся с `@`. Все директивы вычищаются
из текста до отправки: во Flow уходит только чистый промпт.

| Директива | Где | Что делает |
|---|---|---|
| `@project <имя>` | начало файла, до первого блока | проект Flow этой очереди: перед прогоном откроется, при отсутствии — создастся. Резюм считается в рамках проекта |
| `@ref <путь>` | IMG и VID | прикрепить локальный файл референсом. Путь как есть, пробелы допустимы, кавычки не нужны. Можно несколько `@ref` в блоке |
| `@use <id>` | IMG и VID | прикрепить **результат другой задачи**. Это главный якорь связи «кадр → видео» |
| `@duration 4\|6\|8\|10` | только VID | длительность ролика в секундах. Без неё берётся дефолт из `config.yaml` (8s) |
| `@out <имя>` | IMG и VID | имя файла результата вместо `<id>` |

**Неизвестная `@`-строка — ошибка разбора.** Это сознательно: иначе опечатка
`@refs` вместо `@ref` молча уехала бы в текст промпта. Если промпту зачем-то
нужна строка, начинающаяся с `@`, — переформулируй; экранирования нет.

### Как разрешается `@use`

1. Если `<id>` — это IMG-блок **выше по этому же файлу**: берётся его будущий
   результат `out/<id>.*`. Порядок важен — ссылаться можно только назад.
2. Если такого блока в файле нет: ищется готовый файл `out/<id>.*` от прошлых
   прогонов. Нашёлся — используется, нет — ошибка разбора.
3. `@use` на VID-блок — ошибка: референсом может быть только картинка.

Дальше, уже на прогоне, программа превращает файл в элемент библиотеки Flow:

- результат прошлой задачи **этого же проекта** находится по media-uuid из
  журнала — файл вообще не заливается заново;
- внешний файл (`@ref`) заливается в библиотеку **один раз на проект** и
  кэшируется по пути+mtime+размеру — второй `@ref` того же файла в любом блоке
  переиспользует uuid без загрузки;
- прикрепление верифицируется: после «Добавить в запрос» программа пересчитывает
  чипы в панели ввода, и если их меньше, чем ожидалось, задача падает, а не
  генерит с недостающим референсом.

uuid действительны только внутри своего проекта Flow: в новом проекте те же
файлы зальются заново — это нормально.

## 3. Правила и типичные ошибки

Разбор ловит и показывает с номером строки:

| Ошибка | Причина |
|---|---|
| `текст вне блока` | промпт начался до первого `=== IMG/VID` |
| `неизвестный тип` | в заголовке не IMG/VID и не синоним |
| `повтор id` | два блока с одинаковым `<id>` |
| `@ref без пути`, `@out без имени` | пустая директива |
| `@use ждёт ровно один id` | несколько слов после `@use` |
| `@duration 7 — допустимы [4, 6, 8, 10]` | недопустимая длительность |
| `@duration имеет смысл только в блоке VID` | директива в IMG-блоке |
| `@use ... генерится позже` | видео ссылается на кадр, описанный ниже |
| `@use ... указывает на видео` | референсом может быть только картинка |
| `блок без текста промпта` | после директив нет ни одной строки текста |
| `неизвестная директива` | опечатка в `@`-строке |

Ещё три факта, которые полезно знать:

- **Многострочность безопасна.** Текст вставляется в редактор Flow без событий
  клавиатуры, Enter физически не нажимается — промпт на 2000+ знаков с
  переводами строк доходит посимвольно. Никаких «однострочных» версий не нужно.
- Дубли референсов внутри блока схлопываются с сохранением порядка.
- Формат кадра (9:16) и количество (x1) в промпте не указываются — их
  выставляет и проверяет сама программа по `config.yaml`.

## 4. Полный пример эпизода

```
# ЗАСТРЯЛО S01E03 — очередь генерации

# Шаг 1: эталон нового персонажа. Референсов нет — чистая генерация.
=== IMG E03_etalon
Vertical 9:16 frame. Cinematic 3D animated cartoon, Pixar-style...
Full body character sheet of a grumpy molar tooth in a bathrobe...

# Шаг 2: кадры сцены. Эталоны героев — файлами, новый персонаж — по @use.
=== IMG E03_K1
@ref C:\RVL\ZASTRYALO\refs\E01_0A_geroi4.png
@use E03_etalon
Vertical 9:16 frame. The two hunters meet the molar in the doorway...

=== IMG E03_K2
@ref C:\RVL\ZASTRYALO\refs\E01_0A_geroi4.png
@ref C:\RVL\ZASTRYALO\refs\product_RL230.jpg
@use E03_etalon
Vertical 9:16 frame. Close-up: the hunter presents the black irrigator...

# Шаг 3: оживление. Первый @use — кадр-источник.
=== VID E03_K1_anim
@use E03_K1
@duration 8
Animate this image. Slow push-in, the molar squints suspiciously...
DIALOGUE, in Russian: ...

=== VID E03_K2_anim
@use E03_K2
@duration 6
Animate this image. Static camera, steam rises, the molar reaches out...
```

Прогон: картинки идут раньше видео просто потому, что стоят выше. Если процесс
убить и перезапустить, готовые задачи пропустятся (резюм по журналу; в панели
галочками можно принудительно перегнать любую строку).

## 5. Шаблон для LLM, который пишет промпты

Вставь в системный промпт своего генератора сценариев:

```
Выдавай результат СТРОГО в формате flowbatch, без какого-либо текста между блоками.

Первой строкой ставь «@project <название эпизода>» — имя проекта Flow.

Каждая сцена — блок:
  строка «=== IMG <id>» (картинка) или «=== VID <id>» (видео),
  затем директивы, затем текст промпта.

Директивы:
  @ref <абсолютный путь>   — файлы-эталоны персонажей и фото продукта (дам список ниже);
  @use <id IMG-блока>      — у каждого VID-блока ПЕРВОЙ директивой: кадр-источник.
                             IMG-блок может ссылаться @use на более ранний IMG (эталон);
  @duration 8              — у каждого VID-блока (4, 6, 8 или 10);
  @out <имя>               — не используй без явной просьбы.

Правила id: латиница/цифры/подчёркивание, уникальные, у видео id = <id кадра>_anim.
Блоки-кадры всегда идут ВЫШЕ блоков-видео, которые на них ссылаются.
Промпт пиши многострочным, переводы строк разрешены и сохраняются.
Не указывай в промпте соотношение сторон-«9:16» как инструкцию программе —
формат выставляется автоматически; писать «Vertical 9:16 frame» в художественном
тексте промпта можно.
Никогда не начинай строку промпта с символа @.

Файлы-эталоны для @ref:
  <сюда подставь свои пути>
```

## 6. Мини-FAQ

**Почему якоря в тексте, а не колонки в таблице?** Таблица (`--sheet`) тоже
поддерживается и никуда не делась. Текстовый формат нужен для конвейера
«LLM написал → человек вставил → поехало»: промпт и его референсы живут рядом,
их не надо разносить по колонкам руками.

**Что будет, если `@ref`-файла нет на диске?** Задача упадёт со статусом ERROR
и понятным текстом, очередь пойдёт дальше. Проверка «все файлы на месте»
делается заранее прогоном с `--dry-run`.

**Можно ли смешивать языки в промпте?** Да, текст уходит как есть.

**Как проверить формат без генерации?** Вставь текст в панель и нажми
«Разобрать и загрузить» — ошибки покажутся сразу; либо `run --prompts файл
--dry-run` — прогонит всё, кроме нажатия «Создать».
